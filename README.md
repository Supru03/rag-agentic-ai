# RAG-based Agentic AI Chatbot

A Retrieval-Augmented Generation chatbot that answers questions **only** from the
"Agentic AI: An Executive's Guide" eBook. Built with Python, LangGraph, Pinecone and FastAPI.

## Note on model choice
The reference suggested OpenAI models. I could not add OpenAI API credits, so I used free
alternatives with the same architecture:
- Embeddings: `sentence-transformers/all-MiniLM-L6-v2` (384 dimensions, runs locally)
- LLM: `openai/gpt-oss-20b` served by Groq
Switching back to OpenAI only requires changing `config.py`, the two model classes in
`ingestion.py` / `graph.py`, and recreating the Pinecone index with dimension 1536.

## Architecture
Ingestion:
PDF -> PyPDFLoader -> RecursiveCharacterTextSplitter (1000 / 200) -> MiniLM embeddings -> Pinecone (cosine)

Query (LangGraph: START -> retrieve -> generate -> END):
Question -> retrieve (top candidates, deduplicated, short chunks removed) ->
generate (strict grounded prompt + similarity threshold) -> answer, chunks, confidence score

## Setup
Requires Python 3.10 or higher.
```bash
python -m venv venv
venv\Scripts\activate          # Windows  (Mac/Linux: source venv/bin/activate)
pip install -r requirements.txt
copy .env.example .env         # Mac/Linux: cp .env.example .env
```
Edit `.env` and add your own `GROQ_API_KEY` and `PINECONE_API_KEY`.
Place the eBook PDF at `data/Ebook-Agentic-AI.pdf`.

## Run
1. Ingest the PDF (run once only; re-running creates duplicate vectors):
```bash
   python -m src.ingestion
```
2. Start the API:
```bash
   uvicorn app:app --reload
```
3. Open http://127.0.0.1:8000/docs and use `POST /chat`, or run the tests:
```bash
   python tests_sample_queries.py
```

## API
`POST /chat`
```json
{"query": "What role does memory play in Agentic AI workflows?"}
```
Response:
```json
{
  "answer": "...",
  "retrieved_chunks": ["..."],
  "confidence_score": 0.66
}
```

## Design decisions
- **Strict grounding:** two layers. A similarity threshold (`MIN_RELEVANCE`) refuses
  before the LLM is called, and the prompt tells the LLM to answer only from context.
- **Confidence score:** the top Pinecone cosine similarity of the retrieved chunks
  (0 if the model refuses). It is not generated by the LLM.
- **Retrieval debugging:** while testing I found duplicate vectors from a repeated
  ingestion run and that the title page and table of contents outranked real content
  for definition questions. I re-ingested cleanly and added deduplication, a
  minimum chunk length filter, and removal of phrases like "according to the eBook"
  from the search query.
